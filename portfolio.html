▒
dark-first design
OLED displays consume energy proportional to each pixel's brightness. a dark background literally turns those pixels off. this portfolio uses #181c18 as its base background.
dark pixels on OLED = ~0W consumption per subpixel
source: see references → OLED power
◐
desaturated colors
warm, desaturated palettes help keep average luminance low. here the aesthetic tries to serve readability and efficiency without visual excess.
warm muted has lower average luminance than neon
source: see references
⊞
cache-first backend
each avoided request means less CPU, fewer allocations and less network transfer. cache is a simple choice when data can be reused safely.
avoided req ≈ 0.0001g CO₂ not emitted (est.)
source: see references
∅
zero js framework
React, Vue and Angular require the browser to download, parse and execute hundreds of KB before rendering anything. this site uses Vanilla JS by choice: no framework, no unnecessary overhead.
bundle: 0KB framework · measured TTI < 300ms
⇲
server-side rendering
rendering on the server and serving ready HTML moves the work to optimized hardware, away from the user's device battery.
heavy work on the server · lightness on the client
↯
prefers-reduced-motion
this site respects the OS preference for reduced motion. when active, all transitions are removed: less CPU, less GPU, and a better experience for those who need it.
implemented via @media(prefers-reduced-motion)
⊕
gzip compression
gzip compresses HTML and JSON by 70-85%. implemented in the Go backend via stdlib. brotli is possible through a CDN, but depends on infrastructure configuration.
gzip at origin · brotli possible via CDN, not guaranteed
source: see references
◈
right-sized infra
single process before cluster. local cache before an external service. each layer needs to justify its own cost.
minimal infra = lower cost and lower impact

✓ Go — small runtime, low idle use
✓ in-memory cache — no Redis required
✓ gzip via Go stdlib
✓ token bucket rate limiter
✓ vanilla JS — zero app framework
✗ no heavy ORM
✗ no Kubernetes for a personal site
